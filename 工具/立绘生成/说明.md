# 立绘生成 · 照片 → 星露谷像素小人

把一张自拍压成 **48×64 的真像素 sprite**，可选先调模型重绘成星露谷风立绘。
给 `pixel-campus` 配人物立绘用。

和视频里那套的区别只有一处：**多了一道「真像素化」**。
模型出的是「像素风的画」（上万种颜色、带抗锯齿、没有网格）；这一步把它压到固定网格 + 有限色板，
才能跟地图的像素密度对齐。

## 快速开始

```bash
# 服务端版（能用 AI）
node 工具/立绘生成/服务端.mjs      # 或 npm run 立绘
# → http://localhost:5174
```

打开页面 → 展开「**模型设置**」→ 选提供方 → 粘 key → 点「保存并测试」。

```bash
# 单文件版（不需要 node，双击就能开）
工具/立绘生成/单文件版.html
```

单文件版把脚本、样式、示例图全内联了，只能跑本地像素化，AI 两个按钮是灰的 —— 用来在连不上端口时看效果。
改了 `主程序.js` 或样式后跑一次 `node 工具/立绘生成/打包.mjs` 重新生成它。

## 提供方（默认：火山方舟）

| 提供方 | 走什么接口 | 需要填 |
| --- | --- | --- |
| **火山方舟 · Seedream（默认）** | `POST {基址}/images/generations`，参考图以 data URI 放在 `image` 字段 | API Key + 图像模型（`ep-…` 接入点） |
| **Google Gemini** | `generativelanguage.googleapis.com` 的 `generateContent`，图像用 `imageConfig.aspectRatio` | key（AI Studio） |
| **OpenAI 兼容** | `{基址}/images/edits` + `{基址}/chat/completions` | key + 基址（到 `/v1` 这层）+ 模型名 |
| **模拟** | 不发任何请求，回一张内置示例图 | 无 |

为什么默认是方舟：国内网络可直连（实测假 key 返回 401 `AuthenticationError`，说明路径和鉴权都通）；
Gemini 的域名在无代理网络里会超时，OpenAI 也不通。「模拟」只用来验证链路，图不是你的照片。

### 拿 key 的步骤（火山方舟）

1. 打开 `console.volcengine.com/ark`，手机号注册 / 登录；
2. 「开通管理」开通 **豆包 · Seedream**（有免费额度 / 试用期）；
3. 「API Key 管理」创建 API Key 并复制；
4. 「在线推理」创建推理接入点，选 Seedream 4.0，得到 `ep-` 开头的 ID；
5. 页面「模型设置」：提供方选火山方舟 → 粘 key → 图像模型填 `ep-…` → 点「保存并测试」。

「保存并测试」用 1 个 token 的对话验 key，几乎不花钱；成功会显示「连上火山方舟，key 有效」。

## 配置从哪读

优先级：**环境变量 > `.env.local`（页面保存时写入）> 默认值**。

| 环境变量 | 说明 | 默认 |
| --- | --- | --- |
| `AI_PROVIDER` | `ark` / `gemini` / `openai` / `模拟` | `ark` |
| `AI_KEY`（或 `GEMINI_API_KEY`） | 密钥 | 空 |
| `AI_BASE_URL` | 基址（方舟 / OpenAI 兼容） | 按提供方自动 |
| `AI_IMAGE_MODEL` | 图像模型 / 接入点 | `doubao-seedream-4-0-250828` |
| `AI_TEXT_MODEL` | 文本模型（写人设） | `doubao-1-5-pro-32k-250115` |
| `AI_ASPECT` | 出图比例（第 1 步 2:3、第 2 步 3:4 由页面传） | `3:4` |
| `AI_SIZE` | OpenAI 出图尺寸 | `1024x1024` |
| `AI_TIMEOUT` | 单次请求超时（秒） | `180` |
| `立绘端口` | 监听端口 | `5174` |

`.env.local` 由页面写入，已被 `.gitignore` 的 `.env.*` 规则忽略；里面是明文密钥，别提交、别截图外发。

## 后端接口

| 方法 | 路径 | 干什么 | 返回 |
| --- | --- | --- | --- |
| `GET` | `/api/状态` | 当前提供方、有没有 key、模型名（**不回传 key**） | `{提供方, 有密钥, 图像模型, 文本模型, 提供方列表, 模拟}` |
| `POST` | `/api/设置` | 保存提供方 / key / 基址 / 模型到 `.env.local` | 保存后的状态 |
| `POST` | `/api/测试` | 只验证 key 和连通性，不产生生成费用 | `{成功, 说明, 候选模型[]}` |
| `POST` | `/api/生成` | 带参考图生成立绘 | `{图片: base64, 类型, 说明}` |
| `POST` | `/api/人设` | 带参考图生成人设 JSON | `{名字, 等级, 职业, 台词, 生日, 性格, 最爱的食物, 喜欢[], 讨厌[], 宠物}` |

`/api/生成` 请求体：

```json
{ "图片": "<base64>", "类型": "image/jpeg", "提示词": "（可选，默认用 提示词.mjs 里的模板）" }
```

## 报错对照

| 现象 | 原因 / 怎么办 |
| --- | --- |
| `密钥无效或没权限（401/403）` | key 错、项目没开通该模型，或需要代理 |
| `模型/接口不存在（404）` | 模型名写错。点「测试连接」，从列出来的候选里点一个 |
| `配额或频率限制（429）` | 等一会儿或换 key |
| `模型响应超时` | 调大 `AI_TIMEOUT`，或换更快的模型 |
| `连不上模型服务` | 网络/代理/基址问题 |
| `密钥里有非 ASCII 字符` | 复制时带上了中文注释或全角空格 |
| `没有配置密钥` | 去「模型设置」填，或设 `AI_KEY` 后重启 |

## 第 1 步：自拍 → 写实全身照（重点）

第 1 步不是「发个提示词就完事」，它现在是一个有输入、有校验、有补救、可单独重跑的独立阶段：

| 环节 | 做法 |
| --- | --- |
| 构图 | 固定 **2:3 竖构图**（`比例: '2:3'`），全身照 3:4 容易顶头顶脚 |
| 提示词 | `全身照片提示词`：同一个人、写实 7 头身、站直、双脚入画、浅灰纯色棚拍底 |
| 校验 | 产物解码成像素 → 抠掉浅灰底（容差 36）→ `分析全身()` 量高度占比 / 底部留白 / 底部宽度比 |
| 自动补救 | 校验不过就**自动带 `全身加强提示` 再生成一次**，不会连累第 2 步 |
| 还不过 | **停在第 1 步**，不往下跑（否则第 2 步只会把半身照忠实像素化），并弹出两个按钮 |
| 人工干预 | 「**只重做第一步**」重跑第 1 步；「**用这张全身照继续**」直接进第 2 步 |
| 产物 | 中间图带缩略预览和「下载这张全身照」，可当这个角色的设定稿复用 |
| 第 2 步失败 | 「重试」只重跑第 2 步（复用已有全身照），不再烧一次第 1 步 |

### 自测记录

```
合成浅灰底全身图（300×450）→ 是全身=true  高占比 90% · 底部宽度 59% · 抠除 78%
合成浅灰底半身图           → 是全身=false 主体只占画面 40% · 脚下空了 53%
示例半身图（绿底）         → 是全身=false 底部和肩一样宽 99%
合成绿底全身图             → 是全身=true  高占比 88% · 底部宽度 61%
脚底对齐 关/开             → 最低不透明行 61 → 63（48×64 画布）
```

## 两段式生成（默认开）

一段式是「自拍 → 直接像素」，身体的形状是模型一边补身体一边压像素，容易两头都做不好。两段式把它拆开：

```
自拍 ──①全身照片提示词──► 写实全身照 ──②像素立绘提示词──► 像素 sprite ──► 本地像素化
        （补身体、认人）        （可下载）      （只管压风格）
```

- **第 1 段**：`全身照片提示词`，只要求「同一个人的写实全身照」——自然比例（约 7 头身）、站直、双脚入画、纯浅灰背景。输出会显示在结果区下方，**可以直接下载**，当作这个人的全身参考照。
- **第 2 段**：`像素立绘提示词`，输入已经是全身照，所以不再要求「补身体」，只要求「保持姿势和衣服、压成星露谷像素」。
- 两段都失败时才点「重试」：会把 `全身加强提示` 分别拼到两段提示词后面重跑。
- 成本：两段 = 两次图像调用，耗时大约翻倍。

开关在「① AI 生成像素立绘」上面：`两段式：先生成写实全身照，再转像素`。关掉就回到一段式（`生图提示词`）。

后端对应变化：`/api/生成` 多认一个 `阶段` 字段（`全身` / `像素`），只用来决定「没传提示词时用哪段默认」；页面每次都会显式传提示词。

## 自拍 → 全身立绘

输入多半是「头 + 肩」的自拍，但游戏里要的是站在地上的全身 sprite。这一步靠三件事保证：

**1. 提示词明确「不要沿用自拍的构图」。** 不写这句，模型会老老实实给你半身。`提示词.mjs` 里还固定了：

- 全文提示「The input photo is most likely only a head-and-shoulders selfie. Do NOT keep its framing」；
- A-pose：双脚分开约一只脚宽，腿和脚必须完整入画；
- 4.5–5 头身（星露谷就是大头短腿，不写会得到写实八头身）；
- 衣服能看见就沿用配色，看不见就给「衬衫 + 背带裤/长裤 + 靴子」的农场装；
- 纯品红背景，方便一键抠。

**2. 生成后做一次「全身校验」。** `分析全身()` 用三个几何指标判断（都是对抠完背景的图量的）：

| 指标 | 阈值 | 为什么 |
| --- | --- | --- |
| 主体高度占比 | > 50% | 人太小说明构图跑了 |
| 底部留白 | < 15% | 脚要接近画面下沿 |
| 底部宽度 / 最大宽度 | < 80% | **最有效**：脚/腿比肩窄；半身照的底部是肩膀，这一项会接近 100% |

三项都过才算「全身」。没过的话结果区会出现红字说明，并弹出「**用加强提示重试**」按钮 —— 点击会把 `全身加强提示`（“上次腿被裁了，重画，双脚必须完整入画”那段）拼在原提示词后面重新生成。

**3. 脚底对齐。** 像素化最后一步会把最下面一行不透明像素压到画面底边（只往下挪，不往上挪，避免切脚）。
这样所有立绘共用同一条地面基线，进游戏时 `drawImage` 到地面坐标就不会有人浮空或陷地。

## 像素化管线（`像素化.mjs`）

```
源图
 ├─ 抠背景      外圈像素投票定背景色，距离小于容差的变成全透明
 ├─ 定取景框    自动：不透明像素包围盒 → 按目标长宽比补矩形
 │             手动：居中裁 + 缩放 + 偏移
 ├─ 区域平均    每个目标像素吃掉源图一小块，按透明度加权平均（不是 drawImage 缩图）
 ├─ 调色        亮度 / 对比度 / 饱和度，在网格上做，便宜且不糊
 ├─ 中位切分    切成 K 个盒子取平均色 → 色板（确定性，无随机）
 └─ 最近色映射  可选 Floyd–Steinberg 抖动，透明像素保持透明
```

顺序是重点：**先对齐网格再限色**，反过来就只是马赛克滤镜。
半透明一律砍成 0/255，否则放大后会出现一圈灰边。

## 参数怎么调

| 参数 | 干嘛的 | 建议 |
| --- | --- | --- |
| 网格 | 输出尺寸 | 进 `pixel-campus` 用 48×64；更精细用 64×64 |
| 色板数 | 保留多少种颜色 | 16–24 最有星露谷味；>32 开始像照片 |
| 抖动 | Floyd–Steinberg | 风景可开，人物一般关（开久了脸会花） |
| 抠背景 | 纯色键控 | AI 出图必开；照片可试，抠不干净就关掉手动取景 |
| 容差 | 抠背景宽松度 | 品红背景 60–90 够；边缘残色加到 120 |
| 自动裁剪 | 按主体包围盒取景 | 开着最省事；构图不满意就关掉，用缩放/偏移 |
| 脚底对齐 | 最低一行压到画面底边 | 开着，所有人共用一条地面线；做头像卡时可以关 |
| 亮度/对比/饱和 | 最后调色 | 48×64 上很便宜，可以边拖边看 |

## 接进 pixel-campus

导出的 PNG 放到 `public/角色/`，当贴图用：

```js
const img = new Image()
img.src = '/角色/我.png'      // 48×64
img.onload = () => ctx.drawImage(img, x, y)   // 用整数倍放大，别开平滑
```

地图是程序化逐像素画的，立绘得**同一套色板 + 同一像素密度**，否则一眼看出是贴上去的。
